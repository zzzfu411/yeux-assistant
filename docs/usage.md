# 日常使用

## 打开助手

在项目目录运行 `pnpm start`，打开终端打印的地址，用管理员账号和密码登录。浏览器不再要求粘贴访问口令。

首次部署需在电脑上设置管理员：

```bash
# 使用 Compose 时（按提示输入账号和密码，密码不回显）
docker compose --env-file private/runtime.env exec api node dist/scripts/setup-admin.js

# 本地开发已安装依赖时
pnpm admin:setup
```

密码只保存为带随机盐的 scrypt 哈希，位于忽略的 `private/admin-auth.json`。忘记密码时重新运行同一命令；旧浏览器会话会失效。不要把密码写进命令行参数、公开配置或 Git。

界面布局：主导航始终是“今天 / 目标 / 资料”。“今天”是一页手账：左页“等你的事”最多列三件需要你处理的事（待核对的邮件、等你练习或补充的任务、需要处理的失败任务），右页“写下来”只有一个输入框。写下问题、目标，或直接粘贴一份通知，页面会按内容判断要做什么（研究 / 计划 / 答疑 / 办事 / 整理 / 复盘），并在输入框下方盖章说明理由；判断只在本机按规则进行，不调用模型。不对时点页边的标签改选，之后输入不会再改掉你的选择；需要时点“改回识别”。换标签不会清掉已写的内容。电脑上，消息、设备、定时计划、历史、规则与流程和设置直接列在左侧栏下方，账号与“退出”在左下角；手机上导航在屏幕底部，点“更多”打开这些功能和退出按钮。下文的“更多 → X”在电脑上即左侧栏的 X。

登录有效期为 8 小时；刷新和重启服务不要求重复登录，过期后重新登录。通过“更多 → 退出”立即撤销当前会话并清除浏览器会话草稿。连续登录超过每分钟 8 次时需要稍后再试。

端口和绑定地址可保存在私密的 `private/runtime.env` 中（`ASSISTANT_PORT`、`ASSISTANT_BIND`），下次 `pnpm start` 会继续使用。`127.0.0.1` 只允许本机浏览器，手机不能直接访问这个地址。

## 第一次学习

1. **资料**：点击“添加资料”，上传 UTF-8 Markdown/文本，或粘贴讲义内容。仓库有可练习的 `examples/learning-note.md`。PDF/PPT 先按接入说明提取。
2. **今天 → 学习计划**：在“写下来”写学习目标（或在页边选“计划”），例如“分清关系代数的选择与投影，能解释查询的含义”。点击“选择资料”，按课程或标题筛选后勾选材料，也可点击“关联本页”。筛选不会替换已选资料；需要时展开“学习设置”填写预期成果。
3. **创建学习计划**：后台准备计划、讲解和练习。可以关闭页面，稍后从首页待办的“查看进度”或“继续练习”返回。
4. **回答**：在“练习回答”中作答，点击“提交回答”。不填自评时由模型评阅；“已理解 / 还需练习”是本人的自评，会单独记录。
5. **核对**：展开参考资料看原文。模型缺少可核对依据时显示“暂无法判断”，不会自动算作答对；自评单独标为本人反馈。模型评估不等于事实，目标是否完成由你确认。

一轮练习完成后，这条记录保留用于查看和导出，不再接收新答案；点击“查看目标与复习安排”继续查看计划，新的独立问题从“学习答疑”开始。若异常提示练习的学习步骤无法核对，在目标页先“暂停”再“继续学习”，会重新准备练习，原回答仍然保留。

想让助手以后改变讲解方式：在学习页“更多操作 → 记住一条纠正”填写规则，例如“先给反例，再解释定义”。到“资料 → 记忆与偏好”可以修改、停用或查看历史。

## 维护资料

- **添加资料**：相同正文会提示已有资料。点“查看已有资料”继续使用，只有点“仍保存副本”才新增一份。
- **编辑资料**：打开资料后点“编辑资料”，修改标题与正文并保存。每次修改保留旧版本；关闭编辑或刷新不会丢弃草稿。
- **处理冲突**：另一窗口已保存时，先点“载入最新版本，保留输入”。对照后选择“使用最新内容”或“保留输入继续编辑”，再保存。
- **归档资料**：不再参与新检索，原文、旧引用和目标关联仍保留。在资料页把“资料范围”切到“已归档”，可打开并“恢复使用”。目标草稿中的失效关联可通过“移除不可用关联”清理。
- **版本历史**：旧链接展示对应版本的标题、正文与原件。已经准备的练习按当时保存的资料评阅，下一次准备才采用最新的未归档材料。

资料目录每页显示 30 份，可按标题查找使用中或已归档的资料。查找正文关键词使用页面上方的“检索正文片段”，结果可跳到原文并高亮。关联资料最多 100 份，跨课程和跨页选择会保留；“只看已关联”方便检查已有选择。

从 PDF/PPT 等原件提取的资料，只能在页面修改标题；正文需通过原导入流程更新，避免丢失原件和页码依据。

## 首页功能

首页顶部显示“待你处理 / 进行中的目标 / 未读消息”三个计数，点击直接进入对应列表。下面提供五个入口。点击后显示对应的输入说明和按钮；空白时可点“填入示例”，修改后再提交。

| 功能 | 填写内容 | 提交按钮与结果 |
| --- | --- | --- |
| 深入研究 | 问题、验收要求、可选资料与投入档位（直接 / 标准 / 深入卡片） | 开始研究：比较候选、查证原文并迭代；未连接模型时不可提交。详情见 [研究指南](research.md) |
| 学习计划 | 学习目标，可选关联课程资料 | 创建学习计划：准备学习步骤，结合回答持续调整 |
| 学习答疑 | 概念或练习题 | 开始答疑：生成讲解和巩固练习 |
| 整理材料 | 原始材料与输出要求 | 整理材料：生成摘要、要点或草稿 |
| 安排复盘 | 待办或学习记录 | 生成清单：提供安排或复盘建议 |

每项功能的输入分别暂存，切换功能、切页和刷新后可恢复；退出登录会清除草稿。点击功能或填入示例不会创建任务。整理材料和安排复盘生成内容，定时执行需另建“定时计划”。独立任务可检索整个资料库。

首页待办显示“继续练习”“查看进度”或“处理任务”等具体动作。设备控制、资料管理、定时计划和历史记录也可从首页直接打开。

## 邮件

“更多 → 邮件”（电脑左侧栏直接可见）按往来线程整理所有来信与已发邮件，每封都存入个人资料库，可在回答中被引用。

- **邮箱模式**（设置 → 邮箱）：`关闭`、`模拟邮箱`、`真实邮箱（smail）`。模拟邮箱是本机 `private/mail-sim/` 下的文件邮箱，可以完整体验收信、起草、确认发送，不会发出任何邮件；邮件页和线程页的“模拟一封来信 / 模拟对方回信”用来投递测试来信。真实邮箱填客户端专用密码或授权码（只写不回显），“测试已保存的邮箱”逐项检查 IMAP 与 SMTP，不发信。
- **收取**：只读打开收件箱和“已发送”文件夹，不标记已读、不移动邮件。后台每分钟收取（可关闭），也可点“收取新邮件”。线程按 In-Reply-To / References 归并，其次按主题与共同联系人；HTML 邮件转为文本并标明来源；邮件列表与只抄送给你的群发标为“群发”，只保存不起草。
- **起草**：直接发给你的来信会自动生成回复草稿（可改为全部或不自动，另有每日上限）。草稿参考线程里最近的往来、你的资料与“邮件”类规则；缺少必要信息时先列出“回复前需要你补充”，不会编造。收件人不由模型决定。
- **发送**：在草稿页点“核对并发送”，会生成一份固定收件人、主题、正文和版本的确认，再点“确认发送这封邮件”才发出；回复带 In-Reply-To，对方客户端显示为同一会话。结果不明时需要你核实，不会自动重发；同一封来信不会被重复处理。
- **纠正**：改过草稿后可点“从我的修改总结规则”，助手调用一次模型生成规则提议（真实模型约需半分钟：超过 15 秒时页面先提示“正在总结”，完成后收到通知；期间重复点击不会再次调用）；提议只在“资料 → 记忆与偏好”里等待你确认，确认后才写入私密 Git。

## 办理通知

在“今天 → 写下来”直接粘贴通知原文，页面会识别为“办理通知”（也可在页边选“办事”；或在邮件线程点“作为通知办理”，或让流程按邮件主题自动接手），可选择一个已保存的流程。

1. **抽取要素**：活动时间、报名截止、材料截止、地点、联系方式各自附原文引句。程序核对引句确实在原文中、日期与引句一致；截止时间须有“截止 / 之前 / 18:00 前”这类说法，只写了截止的句子不能当作活动开始时间；联系人可以是姓名，但必须原文写明；无法确认的列入“未能确认”。模型原始抽取结果一并保存，之后每次重新准备都按当前核对规则重新检查，不再调用模型。
2. **查个人资料**：对照资料库（含 `profile/` 与以往办事记录）列出材料：已有 / 缺少 / 待确认，并附依据。
3. **追问**：缺少必须的信息时先在手机上问你，你在“补充信息”里回答后继续。
4. **产出**：需要邮件报名时生成一份邮件草稿，仍需你核对后发送。清单和是否需要邮件由一次调用给出；邮件正文另用一次调用撰写，并且只在没有待补充问题、你也没有改过或确认过现有草稿时才写，所以追问那一轮更快，也不会写出注定作废的信。同一轮里写信这一步失败时，自动重试只补写邮件，不重新生成清单。收件人依次取：联系方式里的邮箱、通知中唯一写明的邮箱、通知发件人；都没有或有多个无法区分时，第一条追问就是“邮件应发给谁”，你回答的邮箱会被采用。日期生成 `.ics` 日历文件，截止与活动分开、截止前一天提醒。
5. **归档**：点“完成并归档”，要素（事实）、你的补充、清单与邮件结果（生成内容分节标注）写入 `private/workspace/records/年/月-日-标题.md` 并提交私密 Git，同时进入资料库供以后检索。

“保存为流程”把这次实际用到的步骤、邮件主题关键词和说明保存为 `flows/<标识>.md`（私密 Git）。之后可在首页“常用流程”直接套用，主题含关键词的新邮件也会自动按流程办理。流程不能关闭发送确认，ehall 步骤本轮暂未接入。

## 手机使用

- **安装**：手机用 Safari / Chrome 打开 `https://assistant.yeux.si`，登录后“添加到主屏幕”，以后从图标打开（全屏、带底部导航）。
- **通知**：在主屏幕打开后到“设置 → 手机通知”点“在这台设备开启通知”。新邮件、待确认发送、需要补充的信息和完成的任务会推送到手机；可随时发送测试通知或关闭。
- **首次启用**（只需一次）：在 Cloudflare 为 `assistant.yeux.si` 添加 A 记录指向 VPS（地址见 `private/runtime.env` 的 `ASSISTANT_TUNNEL`；仅 DNS，不开代理），然后在电脑上运行 `sh private/vps/enable-https.sh` 签发证书并启用 HTTPS 站点。
- **连接方式**：数据与模型密钥都留在电脑上。VPS 上的 nginx 只做 HTTPS 入口，经电脑主动建立的 SSH 反向隧道转发到本机实例：电脑上运行 `pnpm start` 与 `pnpm tunnel start`（`pnpm tunnel status` 查看，`pnpm tunnel stop` 关闭）。电脑休眠或隧道断开时手机会看到“暂时离线”，恢复后自动重连，任务不会丢失。若服务器还留着上次的旧连接（日志出现 “remote port forwarding failed”），隧道会只结束占用本隧道端口的旧会话再重连。

## 查找以往记录

“目标”可按状态筛选、按标题查找；“更多 → 历史”可按任务类型、状态和标题查找。每页显示 30 条，使用“上一页 / 下一页”继续查看，点击记录打开完整内容。目标页的学习记录与练习反馈分别翻页。

首页显示最多三项待办，同时显示真实总数。点“查看全部待办”打开完整列表；新增或调整任务后，可点“刷新列表”重新查询。

学习页中，模型提供的判定依据可在“更多操作 → 内容版本 → 评阅核对记录”展开。若评阅完成后准备下一步失败，点击“重试”继续准备，不会重复计算这次回答。

## 设备操作

从首页“设备控制”或“更多 → 设备”进入。当前提供演示台灯，不会操作真实电脑或电器：

1. 填写“设备名称”，点击“添加演示台灯”。默认名称自动递增，每台设备还显示稳定编号；同名设备也可按编号区分。初始状态为关闭。
2. 点击“开灯”。页面自动定位到对应的确认记录，显示设备名称、编号与确切动作，此时尚未执行。
3. 核对后点击“确认开灯”。后台执行并读回状态，成功后显示“模拟状态已核验：开启”。确认在 5 分钟后失效。
4. 使用“关灯”走同样的确认流程。刷新或离开页面不会丢失待确认请求与执行记录；设备卡上的“查看操作”和消息中的“查看操作”可直接返回对应记录。较早的消息也能打开完整记录。

设备页分别展示后台状态与操作记录。后台离线时，已确认的动作会排队，恢复后只有仍在有效期内的动作才可能执行；可以主动取消。页面按服务器时间显示有效期，实际派发仍由后台检查。

卡片显示最近一次核验结果，不是实时遥测。执行中或结果未知时，不继续把旧状态当作当前状态；“刷新记录”更新保存的记录，不直接操作或重新读取硬件。本人核实会保留依据，新的设备读回成功后才重新显示核验状态。

“暂停全部设备”会使未执行的旧请求失效；恢复后需重新选择操作。执行中使用“请求停止”只代表停止请求，不能保证撤销已经发生的动作。结果待核实时，先检查设备，再填写“核实记录”并选择结果；这会保存本人核实的依据，不会重发指令，也不会冒充自动核验。

首台真实设备仍需明确型号/系统、希望执行的操作和连接方式，按 [SPEC 的 D4 验收](../SPEC.md) 单独接入。

## 其他用法
- 暂停或调整学习：进入“目标”，修改材料、成果或复习间隔。
- 模型配置：“更多 → 设置”。保存后再测试连接；密钥留空表示保留已有密钥。可选填写“独立评阅模型”，让深入研究由另一个模型评阅。
- 资料开关：关闭后不向模型发送资料片段和历史生成内容，本次输入和已保存偏好仍会发送。
- 消息、历史和定时计划：在“更多”中查看。等待回答时不会一直调用模型。

## 启停与备份

```bash
pnpm start    # 手动启动；电脑休眠或服务停止期间不执行任务
pnpm status   # 查看服务
pnpm stop     # 停止服务，数据库卷保留
pnpm backup   # 短暂停止写入并备份，再恢复原本运行的服务
```

不会自动登录启动。浏览器关闭不会取消后台任务；需要停止当前生成时，使用学习页“停止”。

本地网络有特殊要求时，可以在 `private/compose.override.yaml` 对 API/Worker 设置 DNS 等 Compose 覆盖；启停和备份脚本会自动使用它，并将此文件纳入备份。不要随意关闭 TLS 验证。

## 启动诊断与备份检查

遇到启动问题，在项目目录运行 `pnpm run doctor`，按提示处理 Docker、配置或端口问题。该命令只检查，不会启动服务或自动改配置。

运行 `pnpm backup` 创建一致备份，再用 `pnpm backup:check <备份目录> --docker` 核对文件并完整解码。需要运行中的 Docker 和本地 PostgreSQL 18 镜像；退出码 0 才表示完整通过。恢复到新实例的操作见 [恢复指南](restore.md)。

## 规则工作区

“资料 → 记忆与偏好”保存已确认纠正后，助手会在 `private/workspace/rules/` 写成 Markdown 并提交本地 Git。模型提出但未确认的内容仍留在数据库，不会自动成为规则文件。

在“设置 → 规则与流程”查看版本与手工修改。手工编辑文件后，点击“载入文件修改”更新索引，再核对改动、填写说明并点击“提交这些修改”。未确认前不会替你提交手工改动。规则被删除时停用并保留历史；错误文件会提示修复；重名 key 冲突的规则停用。

每次模型运行会在会话“本次遵循的规则”中记录实际版本；无模型调用不会伪造采用记录。已有确认规则可通过 `pnpm workspace:import-rules -- --dry-run` 预演，再用 `--apply` 迁入工作区，版本不重编号。容器部署使用 `docker compose --env-file private/runtime.env exec api node dist/scripts/workspace-import-rules.js --dry-run` / `--apply`，并沿用实例自己的 Compose override、端口和数据目录。

`flows/` 目前支持严格格式、版本和 Git 保存；“成功任务保存为流程”、执行流程与从改稿中提议新规则仍待后续阶段。不要把存有流程文件视为流程已经运行。

文件扫描覆盖 `documents/` 与工作区 `notes/`、`records/`、`profile/`。移除的原件退出新检索，历史引用可读；同内容改名提示可能的原资料，不擅自合并记录。个人 profile 不进入普通学习检索。原文链接带有字符范围时可定位高亮；这不表示模型引文已缩短到每一句。
